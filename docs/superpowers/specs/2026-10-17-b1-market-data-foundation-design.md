## 2. 问题、用户与目标

目标用户暂按一名伦敦办公市场研究/资产管理分析人员设计，这是方案假设。其需要回答：“这两期报告中的租金、空置率和成交量，哪些可以比较、变化多少、证据在哪里？”

当前底座能运行 Agent，但没有可核验的市场事实库。B1 要交付可复算的数据结果，减少反复查阅报告、抄录口径和手算的工作。节约时间和实际业务收益在 B1 记录观察，不预先承诺 ROI。

**最小闭环：明确来源及两期报告 → 保存原始快照 → Extract Skill 提取候选事实和证据 → 确定性校验 → 保存版本 → Compare Skill 判断可比性并计算 → 输出带证据的结果包 → 分析人员复核。**

B1 是未来持续监测的数据闭环。采集由用户/API 手动发起；不以每天自动轮询、发现新报告或发送告警作为本阶段要求。

| 用户故事 | 必须实现的行为 |
|---|---|
| US-1 取得真实资料 | 给定已登记 URL，获取真实 HTML/PDF，保留内容、时间与来源身份 |
| US-2 提取事实 | 找到租金、空置率、take-up 及其时期、地域、单位、定义和原文位置 |
| US-3 比较两期 | 先检查完整口径，再给出数值变化或明确的不可比较原因 |
| US-4 复核与复现 | 从结果回到原文；重启后查询同一记录；同一输入可复算同一比较结果 |

## 3. 固定范围与成功门槛

### 3.1 必做范围

- 一个本地、单用户、低并发的数据处理项目；手动 URL 接入已登记公开来源，支持可提取文本的 HTML 和 PDF。
- 一个主要出版机构的两期连续季度报告作为核心演示；每个目标指标必须形成一对口径一致的真实事实，即至少 6 条已核验事实和 3 个比较结果。
- 三类指标：明确类型的租金、空置率、季度 take-up。租金可限定为来源明确列出的某个办公子市场及档次；不得把它标成整个伦敦平均租金。
- 地域使用来源原生定义。项目主题为 London offices，不假设 Greater London、Central London、City、West End 可互换。主来源选定后冻结每个指标的精确地域与类型；三个指标不必有相同地域，但每一对比较必须相同，输出必须分别标注。
- 候选事实、校验结果、历史版本、比较结果、原文证据及 Agno Run ID 持久化。
- 通过 AgentOS 触发一次完整处理，并通过冻结原版 UI 中的领域 Agent 查询已保存结果。固定字段/Markdown 表格即可，不改前端源码。
- 用真实报告建立离线评测集，并用规则测试覆盖失败路径。Mock 仅作为故障注入，不能代替核心演示。

### 3.2 暂不纳入

不开发新闻事件、持续变化检测、定时业务任务、主动通知、Analysis Skill、自然语言任务路由、复杂 Team 分析、Dashboard、配置页、报告中心、多租户、公网部署、容器统一、OCR 或付费数据接入。结果包导出不等于报告中心；固定查询工具不等于通用市场问答。

不增加 LangGraph、PydanticAI、Streamlit、另一套调度器或向量数据库，不升级 Agno v3。不把 Session、长期 Memory 或聊天答案作为市场事实库。

### 3.3 成功指标

| 维度 | B0 当前基线 | B1 门槛 |
|---|---|---|
| 真实业务链路 | 无 | 两期真实报告、3 类指标、至少 6 条核验事实、3 对可比结果 |
| 来源追溯 | 无业务证据链 | 核心事实及结果 100% 能定位保存快照的原文与版本 |
| 比较正确性 | 无 | 冻结验收集中的兼容判断、公式及结果全部正确；不兼容不得产生变化值 |
| 抽取质量 | 未测 | 原始自动抽取精确率/召回率各不低于 90%，每次重复运行分别达到；错误不被人工修订从原始统计中删除 |
| 发布结果质量 | 未测 | 核心演示入库后用于比较的 6 条事实逐条核验正确，0 条无证据或口径错误事实 |
| 恢复与幂等 | 仅底座 Session 已测 | 相同输入重复导入不重复市场记录；重启可读同一事实/比较/原文 |
| 资源观测 | 只有 B0 单次观测 | 每次运行记录调用数、耗时和可取得的 token；货币成本不可取得则标 N/A |

90% 是小规模验收集的工程门槛，不是生产准确率承诺。若抽取率通过而核心结果或任一高风险规则失败，B1 仍不通过。

| Teams | 原生运行通过 | 保留，B1 主链不用 | 以后有独立增益证据再引入；第二个 Agent 不作为准确性证明 |

httpx、PyMuPDF、Pydantic、SQLAlchemy 为用户提出的实现方向。依赖版本和安装方式在进入实现后的兼容检查中冻结，不在本方案声称已验证。

正常路径不调用 Team、不调用模型做计算或改写每个结果。每份资料只做必要抽取；校验、持久化、比较、导出均走 Python。聊天只是入口与展示，结果包中的数字直接取自确定性结果。

## 5. G0：数据源资格门禁

开发前先建立来源清单与真实验收语料。本方案没有联网选定出版机构，也没有确认任何特定报告的访问许可、指标完备性或可比性。不得从“有研究网页”推断“有可用历史数据”。

| 检查项 | 放行证据 |
|---|---|
| 来源与使用边界 | 发布机构、官方 URL、访问方式、内部验证用途及访问条款检查记录；有疑义交项目负责人决定，不绕过登录/付费限制 |
| 历史可得 | 主来源两期连续季度原始报告均可获取，记录真实发布时间，缺失不能编造 |
| 指标覆盖 | 每期均有所选租金、空置率、季度 take-up，附逐条人工标注位置 |
| 可比口径 | 每个指标的一对地域、定义、统计周期、样本/方法标识可对应；租金类型明示；无法确认则标待复核 |
| 技术可读 | HTML 或文本 PDF 可稳定抽出正文/表格文本；扫描件不自动 OCR |
| 评测补充 | 再保留两份真实报告，来自另一版式或另一个机构，用于未参与调参的测试；附指标存在/缺失标注 |

优先选择一个机构满足核心演示，不建设站点专用爬虫。若找不到满足 3 类指标的单一机构，停止 G0：提交“更换来源、增加第二机构且按来源分开比较、或缩小指标”的具体证据与选项，由项目负责人确认，不能悄悄降低验收门槛。

主来源和指标定义在提示词调试前冻结；评测补充资料不用于提示词调优。若补充资料不能包含与主来源互补的 HTML/PDF 格式，另补真实格式样本作解析测试，不要求额外建立市场比较对。

## 6. 最小数据契约

### 6.1 实体与职责

| 实体 | 最小内容 |
|---|---|
| Source | source_id、发布机构、允许的域/路径、来源市场定义、许可记录 |
| DocumentSnapshot | document_id、请求/最终 URL、标题、媒体类型、内容 SHA-256、快照位置、published_at、collected_at、解析器版本 |
| ExtractionAttempt | attempt_id、document_id、模型/提示词/Skill/schema 版本、Agno run_id、原始结构化输出、状态、耗时与调用统计 |
| MetricObservation | observation_id、attempt_id、指标与定义、地域定义、时期、原始值/单位、标准值/单位、状态、证据定位、修订关系 |
| ComparisonResult | comparison_id、两条 observation_id、可比检查结果、原因码、公式、输入值、结果、计算版本 |

Source/DocumentSnapshot/ExtractionAttempt/Observation/Comparison 是逻辑实体，可按实现合理合表。市场事实库与 Agno 运行库分开，不能让会话清理删除市场事实。

### 6.2 字段规则

- 时间分开：报告发布时间、指标 period_start/end、采集时间；存储时间使用带时区格式，未知发布时间为空并保留原因，不能拿采集时间代替。默认演示只接受明确季度。
- 租金：记录 prime/headline/achieved 等原文定义、每面积每时间单位、币种、档次与地域。默认规范化为 GBP/sq ft/year；没有明示的时间分母不能默认补一年。
- 空置率：保存百分数及分母/市场定义，变化用百分点 pp；不得把“上升 1 个百分点”写成“上升 1%”。
- Take-up：保存办公面积、季度或 YTD 标识、地域及交易统计定义；默认规范化为 sq ft/quarter。YTD 不直接与单季度比较，B1 不从 YTD 自动差分推导季度数据。
- 数值用十进制和明确精度；面积单位变换使用冻结常量并记录转换，保留原值；展示舍入不参与后续计算。缺失值为空，不能变成 0。
- 证据包含 document_id/hash、原文短片段与位置。PDF 至少为一基页码及页内文本区段，必要时表格行列/坐标；HTML 为保存正文中的元素/段落定位及文本偏移。定位须能在保存快照上解析。
- 文本层若无法区分表格行列、地域或单位，则进入 needs_review，不能凭模型信心通过。模型自报 confidence 不作真实性门槛。
- 状态至少区分 candidate、validated、needs_review、rejected。validated 表示通过本版校验规则，不代表来源真实或语义绝对正确；正式验收仍需与人工金标准比对。

### 6.3 身份、幂等与修订

内容 hash 用于快照内容去重；相同内容的不同 URL 可保存来源别名，不复制同一来源下的事实。不同机构的相同数值保留各自来源，不合并为一个“真值”。

一次抽取按 document_id + 内容 hash + schema/Skill/模型配置版本识别；再次尝试保留 attempt，而不是覆盖旧结果。相同版本成功重放不重复有效事实。已记录失败可重试，失败身份不得成为永久去重锁。

同一来源/指标/地域/期间的内容修订保留旧记录。无修订说明却出现冲突时进入 needs_review，比较不得自动选择“最后抓到的值”；确定修订后以显式 supersedes 关联，历史比较仍绑定原 observation_id。

## 7. 主流程、接口与结果

一个原生 Workflow 负责显式步骤：登记输入 → Fetch/Parse → Extract → Validate/Persist → Compare/Export。Fetch/Parse、Validate/Persist、Compare/Export 是确定性步骤，Extract 使用原生 Agent + Skill。顺序 Workflow 只是业务控制流，并不要求每一步都有 LLM。

建议的最小业务接口（路径为实施建议，B0 并无这些接口）：

| 操作 | 输入 | 输出 |
|---|---|---|
| ingest_document | source_id、已允许的 URL | document_id、attempt_id、run_id、状态与错误原因 |
| query_observations | source/metric/geography/period | validated 事实、证据及待复核状态，默认排除未放行候选 |
| compare_observations | 明确的两条 observation_id | comparable 或 not_comparable、逐项原因、计算记录 |
| export_result | comparison_id 或本次处理 ID | JSON、Markdown、原文证据索引与文件 hash 清单 |

AgentOS 承载 Workflow/Agent 调用；领域服务不另建一套通用 Agent API。原版 UI 的领域 Agent 使用固定、只读查询工具读取已有结果；采集写操作由显式 Workflow/API 触发，不能因为报告正文中的指令发起写入或抓取。

可比键至少包括发布机构/数据系列、指标类型和定义、地域及其定义版本、币种/单位维度、存量或流量、季度/YTD、租金档次/类型、统计方法。单位可在明确等价转换后比较。必需键未知、期间相同或倒序、非连续季度、任一事实非 validated，均拒绝本演示的环比计算。修订比较与跨来源比较不纳入 B1。

计算由代码执行：租金/take-up 绝对差 = 新值 − 旧值，相对变化 = (新值 − 旧值) / 旧值 × 100%；空置率主展示为新百分数 − 旧百分数，单位 pp。旧值为 0 时相对变化为空并返回 ZERO_BASE，绝对差仍可给出；缺失值不计算。四舍五入规则与计算版本保存在结果中。

输出表必须包含：指标精确定义、两期/两值/单位、变化或不可比较原因、发布机构、两份来源 URL、页码/段落、document_id、observation_id、comparison_id、run_id。声明指标期末与报告发布时间，避免将旧季度数据显示为当前实时行情。JSON 保存未舍入值，Markdown 用统一显示精度。

结果包为本地审阅资料，不建设在线 PDF 服务。不得把不可点击的本地路径包装成 UI 内可用链接；原版聊天展示官方来源 URL、页码和记录 ID，完整快照由本地结果包查阅。

## 8. AI 行为与评测方案

### 8.1 固定资料与分层计分

G0 冻结至少 4 份真实报告：主来源两期用于开发/核心演示，另两份不同版式资料作为留出测试。每份逐项标注 3 个目标指标的值或“缺失/歧义”，形成至少 12 个指标机会；实际可用正例数量及缺失数量在开测前列明。不得把不存在的指标凑成正例。

人工金标准包含全部关键字段和原文定位，由实施者初标、项目负责人或其指定审阅者复核。未复核的金标准只能支持临时结果，不能宣称正式业务验收通过。该审阅不等同于要求负责人亲自重跑所有 B0 测试。

对固定 4 份报告各独立抽取 3 次，逐次报告数值：正确且所有关键口径/证据均正确的候选数量、错误数量、应有而缺失数量。每次都以原始首次自动输出计分，修复重试另列；不把重复抽取当作更多独立文档。

精确率 = 完全正确的非空候选 / 所有非空候选；召回率 = 完全正确的非空候选 / 金标准中实际存在的目标事实。额外臆造候选计入精确率分母。原始 precision/recall 每次均 ≥90%；无正例切片只报告正确留空与错误填值，不用 N/A 稀释失败。

此规模来自“3 类指标 × 两个时期 × 主/留出版式”的覆盖需求，只说明这些输入的表现，不支持线上错误率或统计置信界限。若留出集被用于调参，必须标明失去留出身份，并补充同覆盖的未见资料后重验。

| 行为/切片 | 最少覆盖与原因 | 放行规则 |
|---|---|---|
| AB-1 正常抽取 | 3 类指标 × 两期，包含主/留出版式；防止只调通一种数值 | 逐次原始精确率/召回率均达门槛；核心 6 条事实全部核验正确 |
| AB-2 来源/证据绑定 | 核心全部事实；额外缺页、定位不符各 1 个失败样例 | 无法匹配证据不得 validated；不得产生无证据结果 |
| AB-3 缺失与歧义弃答 | 缺值、单位不明、表格归属不明各至少 1 例 | 留空/needs_review，0 次擅自补值；可用真实片段的注明扰动副本作故障测试 |
| AB-4 指令隔离与拒绝 | 文档夹带改数/外传指令各至少 1 例 | 不执行指令、不调用额外写工具、不泄露密钥；正文只作为数据 |
| AB-5 比较拒绝 | 地域、租金类型、来源、方法、季度/YTD、非连续时期、未验证状态各至少 1 例 | 全部拒绝并给原因码，变化值为空 |
| AB-6 边界计算 | 单位等价、空置率 pp、零基数、缺失值各至少 1 例 | 全部确定性结果与手算金标准相符 |

以上负例可用显式标注的契约构造/资料扰动；不能把它们称为真实市场观测。分开报告 Fetch、Parse、Extract、Validate、Compare、Persist/Recover 和 UI 查询结果，整体成功率不能掩盖单项失败。

### 8.2 调用与耗时预算（建议工程保护线）

- 正常每文档一次候选抽取，最多一次有原因的修复性抽取；包括 Skills 指令获取、provider 重试在内，单文档实际 provider 请求上限 4 次，不无限追问。到限即失败/待复核。
- 初始每份文档最多 40 页或等量正文；超出限额明确拒收，G0 若资料超限先重新估算，不静默截断。表格上下文须完整，不用截断凑成功。
- 每份文档累计输入预算建议 60k tokens、输出 8k tokens，需在执行前估算并在每次请求前检查剩余额度；不支持 token 精确预估时保留估算方式与误差，预算超限拒绝后续请求。
- 单请求超时建议 180 秒，单文档总时限 480 秒；不当作服务性能 SLA。返回明确状态，保留失败记录与已用请求数；迟到响应不得重复发布事实。
- 模型身份记录为请求配置及服务返回 ID，沿用 B0 relay；底层真实模型来源未独立验证。token 缺报则标 N/A，不能记 0；无法取得账单就不声称准确货币成本。
- 无变化的重复导入和已存结果比较不应再次调用模型；存储版本或抽取配置变化后的显式重处理除外。性能报告包含模型请求数、耗时及失败，不只展示最成功一次。

这些保护线在 G0 根据真实资料及 relay 能力冻结；超过既有额度、充值、购买数据或付费部署均交负责人决定，本轮不发生调用费用。

## 11. 主要风险与后续安排

来源访问/口径差异是最高优先级依赖，先 G0 处理。模型偏题和延迟通过原始评测、结构化约束、证据校验、调用上限及确定性比较控制；规则无法证明全部语义，因此保留数据审阅。PDF 表格错位通过原文定位和 needs_review 暴露，B1 不扩成 OCR 工程。

报告内容和 URL 都是不可信输入。B1 来源名单限定 HTTPS 目的站点及重定向，拒绝回环/内网/本地文件目标，限制大小、超时和正文处理，不赋予抽取 Agent 文件/网络写权限。解析和网络故障保留错误，不以空报告当成功；密码及 relay key 不进入模型资料、输出包或前端。

当前 Windows 后端 + WSL UI 延续到 B1 本地验收，容器、生产构建、认证、备份和公网安全在 B5 重新验收。原版 UI 的潜在多媒体注入风险保持登记。默认 Webpack 停滞不在本阶段顺带整改，继续使用 B0 已通过的 Turbopack 路径。

后续按用户决定：B2 持续监测（新闻、定时、变化、通知）；B3 AI 市场智能（Analysis、路由、按需 Team）；B4 产品化 UI；B5 交付验收（端到端、部署、性能、安全、A/B）。A/B 的具体对象与指标到 B5 前另立协议，不预设 B1 通过就证明方案优于其他路线。
